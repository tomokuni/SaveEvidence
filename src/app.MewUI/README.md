# app.MewUI（MewUI 版アプリ本体）

SaveEvidence の **MewUI 版ホストアプリ**です。UI 非依存のコア（`app.Core` / `Platform.Core` /
`Platform.Native` / `LineDetection`）をそのまま使い、UI 層だけを MewUI で実装します。

> **現状: 全ページ実装済み**。キャプチャ / フォルダビュー / Undo 一覧 / 設定の 4 ページと、
> 撮影（スクリーン / ウィンドウ / 範囲）・プレビューの切り出し・履歴の移動・設定の永続化・Native AOT 配布が動作します。
> Avalonia 版 `app.AvaloniaUI` と同じ `settings.json` を共有します。

## 前提

- .NET 10 / Windows 10 以降
- `Aprillz.MewUI` **0.21.1 固定**（API が安定化中（0.x）のため、破壊的変更を避けて固定する）
- MewUI は **コードファースト**（XAML を持たない）。画面は C# のマークアップで組む

## 実行

```powershell
dotnet run --project src/app.MewUI/src/app.MewUI.csproj
```

## 起動に必須の初期化

メタパッケージ（`Aprillz.MewUI.Windows`）を参照しても、**バックエンドとプラットフォームホストは自動登録されません**。
`Application.Run` の前に明示登録が必須です（忘れると例外または無言終了）。

```csharp
Direct2DBackend.Register();        // 描画バックエンド
Win32Platform.Register();          // プラットフォームホスト
SkiaDirect2DInterop.Register();    // Direct2D ⇔ Skia のブリッジ（未登録なら CPU 転送経路になる）
```

## ナビゲーション

ページの内容は**選択時に 1 度だけ生成**し、以降は同じ要素を表示します（ページの状態と変更購読を保つため）。
一方、「表示されるたびに最新化する処理」（設定の再読込・一覧の再構築）は `PageContent.OnActivated` として
渡し、ナビ項目の選択時に呼びます（Avalonia 版が `IsVisible` の変更で行っている処理に相当）。

ナビパネルは Avalonia 版と同じ見た目にするため、`NavigationView` を使わず**自前の合成**で組んでいます
（`NavigationView` はペインの余白と区切り線が固定で、アイコンも指定できないため）。

| 項目 | Avalonia 版と同じ仕様 |
| --- | --- |
| 幅 | 展開 180 / 収納 40（`MainViewModel.NavPanelWidth`） |
| アイテム | アイコン（16 DIP） + ページ名（展開時のみ表示）。選択中は背景色で示す |
| 余白・区切り線 | なし（ページとの境界線も描画しない） |
| ヘッダー | 左上のトグル（開閉）とアプリ名。先頭ページを選択した状態で起動する |
| 開閉の保存 | 開閉状態は設定へ保存し、次回起動時に復元する |

**アイコン**: Avalonia 版と**同一の SVG ファイル**（`app.AvaloniaUI/src/Icons/*.svg` を埋め込みリソースとして共有）を
`SKPath.ParseSvgPathData` で読み、Skia で 32 px にラスタライズして `Image` へ渡します（テーマ変更時に色を更新）。

| 項目 | 仕様 |

| 最小サイズ | `800 x 400`（DIP。Avalonia 版 `MainWindow.axaml` の `MinWidth` / `MinHeight` と同じ） |
| タスクバーアイコン | Avalonia 版と同じアイコン（`ic_fluent_scan_table_24_regular.svg`）を PNG 化し ICO へ詰めて設定 |

## ナビゲーション（OnActivated の処理）

| ページ | OnActivated の処理 |
| --- | --- |
| キャプチャ | なし（ViewModel の変更通知で追従する） |
| フォルダビュー | 保存済みの表示モード・ソート順を復元し、一覧を再構築する |

## グローバルホットキー

設定に保存されたホットキー（スクリーン / ウィンドウ / 範囲選択）をアプリ起動時に登録し、押下でキャプチャを開始します。
登録は **初回描画後（`FirstFrameRendered`）** に行います。起動時コールバックでは、ウィンドウハンドルが未確定または
MewUI 側のウィンドウプロシージャ設定で上書きされ、`WM_HOTKEY` を受け取れません（実測）。

## キャプチャ

| 種別 | 操作 |
| --- | --- |
| スクリーン選択 | カーソル下のモニターをハイライトし、クリックまたは Enter で確定する |
| ウィンドウ選択 | カーソル下のウィンドウをハイライトし、クリックまたは Enter で確定する |
| 範囲選択 | ドラッグで矩形を指定し、Enter で確定する（矢印キーで微調整できる） |

- 確定した領域を切り出し、プレビューへ設定します（撮影前の画像は Undo 履歴へ退避）。
- Escape でキャンセルします（プレビュー・履歴・ステータスとも変更しません）。
- **対象は全モニター（仮想スクリーン）** です。1 モニターに限定するとカーソルのあるモニターでしか選択できないため、全モニターを 1 枚の画像として扱います（Avalonia 版と同じ）。
- 範囲選択の切り出しは**閉区間**（始点・終点のピクセルを含む）です（Avalonia 版と同じ規則）。
- **自ウィンドウの写り込み防止**: 設定 `HideMainWindowOnCapture` が true のとき、メインウィンドウを
  **画面外へ退避**してからオーバーレイを表示します。非表示（`Hide`）は復帰時のウィンドウ再作成で
  ちらつくため、位置の変更（画面外配置）で代用します（Avalonia 版と同じ方式）。
  併せて **キャプチャ除外（`SetCaptureExclusion` = `WDA_EXCLUDEFROMCAPTURE`）も設定**し、撮影後に解除します。
- **オーバーレイ表示時のちらつき防止**: ウィンドウは表示時に背景色で塗られるため、そのまま表示すると
  撮影画像を描くまでの数十 ms（実測: 65 ms）が背景色の面として見えます。透明な状態で表示して
  画像が合成されたフレームで透明を解除し、背景色は撮影画像の平均色に合わせて差を目立たなくします。

## プレビューの切り出し

ツールバーの「切り出し」ボタンで、プレビューの上へ領域選択のオーバーレイを重ねます（もう一度押すと確定、選択なしならキャンセル）。
確定した領域は現在の画像から切り出され、Undo 履歴へ退避されます（「自動切り出し」と同じ経路）。
切り出しは**閉区間**（始点・終点のピクセルを含む）です（Avalonia 版と同じ規則）。

選択中は選択矩形の左上に 2 行のラベル（サイズラベル / 操作ラベル）を表示します。

## 自動切り出し

☰ メニューの「Crop - 自動切り出し」でプレビュー画像からウィンドウ枠を検出し、切り出し範囲を提示します。

| 操作 | 動作 |
| --- | --- |
| 実行 | 検出した矩形を**水色の実線枠**（2 DIP）で表示する（Avalonia 版と同じ） |
| カーソル移動 | カーソルを含む矩形のうち**面積が最小**のものを**赤色**で強調する |
| 矩形内のダブルクリック | その矩形で切り出す（Undo 履歴へ退避し、「切り出し」と同じ経路） |
| 矩形外のダブルクリック | キャンセルする（検出矩形を消し、画像は変えない） |
| Escape | キャンセルする（切り出しモードと同じ操作） |

矩形のヒット判定は `MainViewModel.HitDetectedRect`（コア）が単一所有し、両 UI が同じ判定を使います。

## 選択中のラベル

撮影・切り出しのオーバーレイは、選択矩形の左上へ行を縦に積んだラベルを表示します。

| 行 | 内容 | 設定（「外観設定」） |
| --- | --- | --- |
| 1 行目 | サイズラベル（座標・幅×高・表示倍率） | 表示可否 / 文字サイズ / 文字色 / 背景色 |
| 2 行目 | 操作ラベル（確定・キャンセルの方法） | 表示可否 / 文字サイズ / 文字色 / 背景色 |
| 3 行目 | 情報ラベル（ウィンドウ選択時のウィンドウタイトル） | 表示可否 / 文字サイズ / 文字色 / 背景色 |

座標は画像ピクセルで表示し、日本語を含む文言もそのまま表示できます（字形を持つフォントへ自動フォールバック）。

## 撮影オーバーレイの挙動

撮影中（スクリーン選択 / ウィンドウ選択）のオーバーレイは次のように動作します。

- カーソル下の要素をハイライトし、**左クリック**または **Enter** で確定します（右クリックでは確定しません）。
- 要素を検出できない位置（ウィンドウ選択でデスクトップ上など）をクリックしても確定しません（キャンセルは Esc）。
- **Esc** または他ウィンドウへの切り替え（非アクティブ化）でキャンセルします。
- 撮影中はタスクバー・Alt+Tab の一覧に表示しません（一時的な表示のため）。

## 保存（上書き確認）

ツールバーの保存アイコンは、保存先フォルダへファイル名テンプレートから生成した名前で書き込みます。
同じ名前のファイルが既にある場合は、オーナーの中央へ確認ダイアログ（「はい」/「いいえ」）を表示します。
「はい」で上書き保存し、「いいえ」・Esc・ダイアログを閉じる場合は保存しません。

## 一覧のアイテム（フォルダビュー / Undo 一覧）

Avalonia 版と同じ見た目です。

- サムネイルは**画像の縦横比のまま**表示し、周囲へ**影**を付けます。行間はアイテムの高さに応じて決まり、
  **行内ではファイル名（ラベル）の位置が揃います**（下端揃え）。
- ファイル名は画像の直下へ置きます（アイテム内の画像背景は一覧の背景色）。
- アイテムにマウスを重ねると、項目全体が薄いグレーの帯でハイライトされ、枠が青になり、影が消えます
  （Avalonia 版の `ListBox` 項目のホバー帯と `:pointerover` スタイルに合わせています）。
  Undo 一覧の「現在」は常に青の太枠で、影を付けません。

## ツールバーとステータスバー

Avalonia 版と同じ配置・同じアイコンです。

| 位置 | 内容 |
| --- | --- |
| ツールバー左 | ☰（メニュー。画像を保存 / コピー / 貼り付け / 元に戻す / 元に戻すを取り消す / 撮影 3 種 / 切り出し / 自動切り出し） |
| ツールバー | ファイル名テンプレート / 保存 / スクリーン選択 / ウィンドウ選択 / 範囲選択 / 切り出し（すべてアイコン。ツールチップ付き） |
| ステータスバー左 | ポインタ座標（固定幅） / 画像サイズ（固定幅） / 保存済み/未 / 保存ファイル名 / 通知メッセージ |
| ステータスバー右 | 拡大率（⊖ / スライダ（10〜500%） / ⊕ / Fit / % 表示） |

- ツールバーはページごとに内容が異なります（Avalonia 版と同じ）。キャプチャは上表のとおり、フォルダビューは「最新の情報に更新 / 特大・大・中 / ▲昇順・▼降順」、Undo 一覧は「特大・大・中」です。
- キャプチャページのツールバーは横幅に収まらない場合に折り返します（Avalonia 版と同じ `WrapPanel`。ファイル名テンプレートが長い場合もアイコンがウィンドウ操作ボタンへ重なりません）。
- グループの区切りには縦の細線を入れます（Avalonia 版の `Separator` と同じ位置）。
- ☰ のメニューはグループを横線で区切り、ショートカット（Ctrl+S / C / V / Z / Y / R）を右端へ表示します（表示のみ。Avalonia 版の `MenuItem.InputGesture` と同じ）。
- ステータスバーの背景色はページ背景と同じで、高さは内容に合わせます（キャプチャはスライダの 24 DIP が決めます）。
- ステータスバーの右端は、フォルダビューが「保存先フォルダ」、Undo 一覧が「ダブルクリックで外部ツール表示」です（右寄せ）。
- 余白は Avalonia 版と同じ値です（左右 4・上下はキャプチャ 1 / 一覧 2）。
- % 表示をクリックすると拡大率の一覧（自動 / 10〜500%）が出ます。「自動」はウィンドウに合わせる（Fit）へ戻します。
- マウスホイールはパン（`Shift` 併用で横）、`Ctrl` 併用でポインタ位置を中心としたズームになります。

- 変更はその場で設定ファイルへ保存されます。

## テーマ（明色 / 暗色）

設定の「テーマ」でライト / ダーク / システムを選べます。**保存したテーマは起動時にも適用されます**。
ページ背景・ナビパネル・一覧・プルダウン・設定のカードなどはテーマに追従し、
ツールバーのアイコンと市松模様の背景色も切り替え時に更新されます。
面の色は Avalonia 版の実測値と同じです。

| 面 | 明色 | 暗色 |
| --- | --- | --- |
| ページ（ウィンドウ） | `#FFFFFF` | `#000000` |
| ナビパネル | `#E6E6E6` | `#1F1F1F` |
| 一覧（フォルダ / Undo） | `#F2F2F2` | `#2B2B2B` |

## プレビューの背景（市松模様）

画像の透明部分とレターボックスは**市松模様**で表示します（Avalonia 版と同じ）。
サイズ・色 A / 色 B は設定（「外観設定」）の `PreviewCheckerSize` / `PreviewCheckerColorA` / `PreviewCheckerColorB` に追従します。
市松模様の色は半透明のため、下地（明色テーマは白・暗色テーマは黒）と合成して表示します（実測で明色 229 / 暗色 199、ダークは明色 73 / 暗色 50）。

## ルーペ（切り出し中のみ）

プレビューのルーペは**切り出し中（切り出しボタンを押した後）だけ**表示し、カーソル位置を拡大して右下（設定のオフセット）へ追従します（Avalonia 版と同じ）。
切り出しを確定またはキャンセルすると消えます。

- 拡大中心はカーソル位置を画像ピクセル座標へ変換し、画像の範囲へクランプした値です。
- 表示位置は `LoupePositionCalculator`（コア）が決めます（オフセットと親領域内へのクランプ）。
- サイズ・拡大率・色・座標ラベルは設定（設定ページの「外観設定」）に追従します。
- 市松模様の下地にはテーマの背景色を塗ります（市松色は半透明のため、下地がないと後ろのプレビュー画像が透けて見えます）。
- 撮影・切り出しの選択中は、ルーペ画像へ**選択矩形の破線**（2 色交互）を重ねて表示します（色は設定の「ルーペ選択矩形の色 A / B」に追従）。

## 操作ログ

マウス・キーの操作ログは Avalonia 版と同じファイルへ出力されます。

- 出力先: `%LOCALAPPDATA%\SaveEvidence\logs\SaveEvidence.log`（日次ローテーション・7 日保持。Serilog）
- 内容: アプリ起動 / 終了、撮影・切り出しの開始と確定・キャンセル、選択操作（MouseDown / MouseUp / DragStart / KeyDown 等）、ズーム操作（前後のズーム率）、ルーペの状態変更（表示中の選択オーバーレイ）、未処理の例外
- 未処理の例外は、アプリ全体（`AppDomain`）/ UI スレッド（`Application.DispatcherUnhandledException`）/ 待機されなかったタスク（`TaskScheduler`）の 3 経路を記録します。UI スレッドの例外は記録後に処理済みとして扱い、ウィンドウの表示を維持します（Avalonia 版と同じ）。
- カテゴリはクラス名（`Program` / `CaptureOverlay` / `CropOverlay` / `CapturePage` 等）で、`[DragRect]` / `[FadeMask]` / `[LoupeCtrl]` / `[ZoomIn]` の各ログは各コントロールが出力します。

## 履歴（戻す / やり直し）

ツールバーの ☰ メニューの「元に戻す」「元に戻すを取り消す」で編集履歴を移動します（画像がある場合のみ有効）。
撮影と切り出しの直前に現在の画像が履歴へ退避されるため、撮影前・切り出し前へ戻せます。
履歴の実体は `UndoStack`（コア、最大 5 段）が保持し、復元した画像の所有権はプレビューへ移ります。

## 配布形態（Native AOT）

配布物は **Native AOT**（`buildScript/MewUI_publish_aot.bat`）です。マネージドコードは全て exe へ
コンパイルされ、ネイティブライブラリ（SkiaSharp / OpenCvSharp）だけが隣に並びます。

| 方式 | 構成 | サイズ（実測） |
| --- | --- | --- |
| Native AOT（既定） | exe 1 個（11.6 MB）+ ネイティブ DLL 2 個 | 84 MB / 3 ファイル |

- AOT のリンクには Visual Studio の C++ ビルドツール（`link.exe`）が必要です。
- ネイティブ DLL は `OpenCvSharpExtern.dll` / `libSkiaSharp.dll` の 2 個です。OpenCV は縮小構成
  （`OpenCvSharp5.runtime.win.slim`）のため、動画入出力（`videoio`）と FFmpeg
  （`opencv_videoio_ffmpeg500_64.dll` 約 31 MB）を同梱しません（本アプリは動画を扱わない）。
- **設定の読み書きには JSON ソース生成が必須**です。反射ベースのシリアル化はトリミングで設定項目が
  削除され、設定が空（`{}`）になります。アプリ本体は `SettingsJsonContext` を `SettingsService` へ
  注入しています（コンテキストは `Settings` を参照する側のアセンブリに置く必要があります）。

## レイアウト（実測済み）

キャプチャページは **3 行の `Grid`（`Rows("Auto,*,Auto")`）** で組み、プレビューを Star 行に置きます。
プレビューは `CropViewControl.MewUI`（ドラッグでパン・Ctrl+ホイールでズーム・検出矩形のオーバーレイ）で、
その上へ `OverlayHost`（絶対配置の領域）でルーペを重ねます。
ウィンドウを縮めるとナビがコンパクト表示になり、プレビューも追従します（`mewui-resized.png` 参照）。

```text
┌─────────────┬──────────────────────────────┐
│ Navigation  │ ツールバー（保存 / ズーム操作）│
│   View      ├──────────────────────────────┤
│  PaneWidth  │ CropView（Star = 残余）       │
│   200       │   └ 矩形オーバーレイ          │
│             │            ┌──────────────┐  │
│             │            │ ルーペ（右下）│  │
│             ├──────────────────────────────┤
│             │ ステータス（Auto）            │
└─────────────┴──────────────────────────────┘
```

ルーペはカーソル位置を拡大し、カーソルの右下（設定のオフセット）へ追従します。
カーソルがプレビューの外にあるときは画像の中央を右下（余白 16 DIP）に表示します。
表示位置は `LoupePositionCalculator`（コア）が単一所有し、ホストは配置フェーズでその結果を適用します。

その他の実測事項:

- **`SkiaCanvasView` は静的画像に対して連続再描画しない**。既定の `ContinuousAnimation` は `true` のため、
  静止画では `false` にし、画像差し替え時に `InvalidateVisual()` を呼びます。
- **`Rect` / `Size` は負のサイズを 0 にクランプ**します（Avalonia は保持する）。
- **`Grid` の行割当**は `Row()` を明示せず `AutoIndexing`（既定）に任せて問題ありません
  （Star 行の後に `Auto` 行を置いても正しく配置されます）。

## 検証

`verify-ui.ps1` は次を自動で行います（GUI の目視に頼らない）。

1. `%LOCALAPPDATA%\SaveEvidence\settings.json` を退避する
2. アプリを起動して `MainWindowHandle` を取得する
3. `PrintWindow`（`PW_RENDERFULLCONTENT`）で撮影し、`mewui-initial.png` に保存する
4. 画素を実測し、プレビューの充填・ステータスバーの表示・ルーペ（設定の枠色の画素数と座標ラベルの白）を判定する
5. ウィンドウを縮めて撮影し（`mewui-resized.png`）、追従を確認する
6. プロセスを終了し、退避した設定を復元する

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File src/app.MewUI/verify-ui.ps1
```

> **重要（実測の落とし穴）**: 検証スクリプト側のプロセスを **Per-Monitor V2（`SetProcessDpiAwarenessContext(-4)`）**
> にしてください。未対応だと座標と撮影が `96/dpi` に仮想化され、ウィンドウの下端・右端が切れた画像になるため、
> **「レイアウトが壊れている」と誤判定します**（実際に誤判定し、存在しない MewUI の制約を記録してしまいました）。

> **注意**: `MainViewModel` は `%LOCALAPPDATA%\SaveEvidence\settings.json` を読み書きします。
> 手動で起動して検証する場合も、事前に退避し終了後に戻してください。

### フォルダビューの検証

保存先フォルダを検証用の一時フォルダへ差し替え、サンプル画像を置いて撮影します（ユーザーの保存先を汚しません）。

| 手順 | 内容 |
| --- | --- |
| 1 | `.work/folderview-samples` を作り、大きさの異なる PNG と画像でないファイルを置く |
| 2 | 設定の `SaveFolderPath` だけを検証用フォルダへ差し替える（他の項目は退避して復元する） |
| 3 | アプリを起動し、`PrintWindow` で撮影する |
| 4 | 画素を実測し、各画像の色・枠線の存在・一覧の描画を確認する |
| 5 | `WM_CLOSE` で正常終了させ、退避した設定を復元する |

**実測結果の例**（1200 × 1200 / 800 × 400 / 400 × 800 / 120 × 120 の PNG + テキスト 1 件）:

- 一覧は 4 件（画像でない 1 件は除外）、名前の昇順で並ぶ
- 正方形の枠内にアスペクト比を保って収まり、余白には枠の背景（濃いグレー）が見える
- ツールバーは「最新の情報に更新」「特大 / 大 / 中」「▲ 昇順 / ▼ 降順」で、保存済みの選択が復元される
- ステータスバーに「4 個のアイテム」「大」「名前の昇順(▲)」とフォルダパスが表示される

### キャプチャの検証

グローバルホットキーを送出し、オーバーレイの表示・選択・確定までを自動で確認します。

| 手順 | 内容 |
| --- | --- |
| 1 | 設定を退避する |
| 2 | アプリを起動し、メインウィンドウを撮影してプレースホルダ画像を確認する |
| 3 | `Ctrl + Shift + E`（範囲選択）を送出する |
| 4 | プロセスの別ウィンドウ（`SaveEvidence キャプチャ`）を見つけ、撮影する |
| 5 | オーバーレイ上をドラッグして矩形を指定し、撮影する |
| 6 | Enter を送出して確定し、メインウィンドウを撮影する |
| 7 | 設定を復元して終了する |

**判定**（画素実測）: 撮影前後でプレースホルダのグラデーション画素数が消え（cool 69,498 → 927 / warm 80,849 → 181）、
プレビュー中央が暗色（138,142,133 → 34,36,36）になれば差し替えが成立しています。

> **注意**: 撮影は**画面から直接コピー**（`CopyFromScreen`）してください。非表示→再表示を経たウィンドウは
> `PrintWindow` が古いフレームを返し、「プレビューが変わっていない」と誤判定します（実際に誤判定しました）。

> **注意**: ドラッグは**画像の表示範囲内**で行ってください。画像外から始めたドラッグは
> クランプ（`ClampToDomainBounds`）により選択が成立せず、「切り出しが動かない」と誤判定します（実際に誤判定しました）。

### ウィンドウ配置の保存・復元

| 手順 | 内容 |
| --- | --- |
| 1 | 設定の `MainWindowBounds` に既知の値（例 `150, 180 / 900 × 600`）を書き込む |
| 2 | アプリを起動する |
| 3 | `GetWindowRect` を実測する（枠 18 × 47 を加えた値になる） |
| 4 | `WM_CLOSE` で正常終了する（強制終了では `Closed` が走らない） |
| 5 | 設定を読み、書き戻された位置・サイズを確認する |
| 6 | 退避した設定を復元する |

**実測例**: `150, 180 / 900 × 600` を指定 → 復元後 `X=150 Y=180 W=918 H=647`（クライアントは `900 × 600`）。
リサイズ後の `1100 × 800` は `X=100 Y=120 / 1082 × 753`（クライアント領域）として保存される。

> **注意**: `SetWindowPos` などでウィンドウを動かすと、終了時にその値が設定へ保存されます。
> 検証後は必ず元の値へ戻してください。
